# browser-vscode —— T4 Level 0 / Level 1

用原生 HTML / CSS / JavaScript 复刻的 vscode.dev 界面（VS Code 网页版）。
视觉基准是 vscode.dev 打开「未打开文件夹」状态时的欢迎页，配色取 VS Code
默认暗色主题 **Dark Modern**。

Level 0 是静态界面；Level 1 在此基础上接上「获取文件内容并进行操作」：
资源管理器里是一棵可展开的文件树，点文件就能读到它的内容并显示在编辑器里。

## 需求对照（T4 Level 0 静态的 vscode）

| 题目要求 | 实现情况 |
| --- | --- |
| 先规划文件夹与项目结构，不着急写代码 | 见「项目结构」，按 `styles` / `scripts` 分层，一个文件一件事 |
| 先实现静态界面，欢迎界面随意 | 顶部提示条、标题栏、活动栏、侧边栏、标签页、欢迎页、状态栏全部还原 |
| 侧边栏 = 左边的功能选择区 + 右边的功能展示区 | 左侧 `activity-bar`（菜单 + 6 个功能图标 + 账户/管理），右侧 `sidebar` 面板区 |
| 侧边栏拖拽调整宽度，达到阈值会消失 | `sash` 分隔条拖拽；宽度 < 120px 松手即收起，双击恢复默认宽度 |

题目限制的遵守情况：

* 不用 Monaco、不用拖拽库——拖拽用原生 Pointer Events 手写；
* 不用任何组件库 / UI 库 / CSS 框架；图标是页面内的内联 SVG，不引图标字体；
* 只用原生 HTML/CSS/JS，无构建步骤、无依赖。

> 脚本用「普通 `<script defer>` + 立即执行函数（IIFE）」组织，而不是 ES Module。
> 原因是浏览器不允许 `file://` 页面加载 ES Module（会被 CORS 拦下），
> 用普通脚本才能保证**双击 HTML 文件直接打开**时交互功能正常工作。

## 需求对照（T4 Level 1 获取文件内容并进行操作）

| 题目要求 | 实现情况 |
| --- | --- |
| 资源管理器里显示工作区的目录结构 | `scripts/explorer.js` 把工作区渲染成文件树，文件夹可折叠 / 展开，展开状态记进 localStorage |
| 获取文件内容 | `scripts/workspace.js` 提供统一读取接口：本地文件夹走 File System Access API 按需读取，内置示例工作区直接读内存 |
| 把内容显示出来 | `scripts/editorTabs.js` 点文件开一个标签页，编辑器里按行号显示内容，状态栏同步语言和行数 |
| 打开自己的文件夹 | 侧边栏「打开文件夹」按钮调用 `showDirectoryPicker()`，选中后能浏览真实磁盘上的文件 |

几个边界情况的处理：

* 二进制文件（含 `\0`）不硬读，提示「只做文本内容预览」；
* 超过 512 KB 的文件跳过读取，避免把页面卡住；
* 浏览器不支持 File System Access API 时（比如 Firefox），示例工作区照样能用；
* 修改内容属于 Level 3，所以这一层明确是**只读预览**。

## 项目结构

```
browser-vscode/
├── bingyan-internship.html # 入口（双击它打开）+ 内联 SVG 图标雪碧图
├── styles/
│   ├── theme.css           # 主题令牌（配色 / 尺寸 / 字体 / 圆角）
│   ├── base.css            # 重置、滚动条、拖拽时的全局状态
│   ├── layout.css          # 提示条、标题栏、工作区、状态栏骨架
│   ├── sidebar.css         # 活动栏、侧边栏、按钮、拖拽条
│   ├── editor.css          # 标签页骨架、欢迎页、演练卡片、底部提示、浮动按钮
│   ├── explorer.css        # 资源管理器文件树（Level 1）
│   └── editor-tabs.css     # 标签页列表 + 文件内容预览（Level 1）
└── scripts/
    ├── main.js             # 入口，组装各模块
    ├── sidebar.js          # 侧边栏宽度拖拽 / 收起 / localStorage 持久化
    ├── activityBar.js      # 活动栏与侧边栏面板联动
    ├── workspace.js        # 工作区（文件系统）抽象层：示例工作区 / 本地文件夹（Level 1）
    ├── explorer.js         # 文件树渲染与交互（Level 1）
    └── editorTabs.js       # 标签页与文件内容预览（Level 1）
```

## 运行方式

**方式一（推荐）：直接双击 `index.html`。** 双击即用，不需要任何服务器或安装依赖，
因为这个项目里没有用 ES Module、也没有任何 fetch 请求。

**方式二：起一个本地服务**（想用 Live Server 之类工具时）：

```bash
python -m http.server 8000
```

然后访问 <http://localhost:8000/>。

两种方式效果完全一致。注意整个文件夹要一起拷贝，`styles/` 和 `scripts/`
两个子目录的相对位置不能变，否则页面会丢样式。

## 交互说明

| 操作 | 效果 |
| --- | --- |
| 拖动活动栏与侧边栏之间的分隔条 | 调整侧边栏宽度 |
| 宽度拖到 120px 以下再松手 | 收起侧边栏（分隔条一起隐藏） |
| 双击分隔条 | 恢复默认宽度 380px |
| 点击活动栏图标 | 切换侧边栏显示的视图 |
| 再次点击当前高亮的图标 | 收起 / 展开侧边栏 |
| 聚焦分隔条后按 ← → | 以 10px 为步长调整宽度（按住 Shift 为 40px） |
| 聚焦分隔条后按 Home | 恢复默认宽度 |
| 点击文件树里的文件夹行（或它的箭头） | 展开 / 收起该目录（真实目录此时才去读） |
| 点击文件树里的文件 | 在编辑器区打开一个标签页并显示文件内容 |
| 拖动光标到标签上点中键 / 按 Ctrl+W | 关闭标签页 |
| 聚焦文件树后按 ↑ ↓ | 在可见行之间移动 |
| 聚焦文件树后按 → / ← | 展开 / 收起目录（在文件上按 ← 回到父目录） |
| 聚焦文件树后按 Enter | 打开文件 / 切换目录 |
| 点工具栏「刷新」 | 丢掉已缓存的目录列表重新读取 |
| 点工具栏「全部折叠」 | 收起所有目录 |

侧边栏宽度与收起状态写入 `localStorage`（key：`browser-vscode.sidebar`），刷新后保持。
文件树的展开状态写在 `browser-vscode.explorer`。

「打开文件夹」用的是浏览器的 File System Access API，目前只有 Chrome / Edge 支持；
其他浏览器会提示不支持，这时内置的示例工作区照样能浏览、能读文件内容。

## 尺寸常量的位置

最小宽度、默认宽度、收起阈值都定义在 `styles/theme.css` 的 CSS 变量里，
`scripts/sidebar.js` 通过 `getComputedStyle` 读取，避免 JS 与 CSS 各存一份。
